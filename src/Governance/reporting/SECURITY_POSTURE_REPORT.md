# Security Posture Report Cadence for TeachLink

## Overview
This document defines the official security posture reporting policy for **TeachLink Web (`Webrinafcode/teachLink_web`)**. Regular reporting on security metrics, vulnerability trends, and mitigation efforts ensures transparency and proactive risk management across the project's infrastructure and codebase.

---

## 1. Metrics Disclosed
Each security posture report must evaluate and publish the following key metrics:
- **Vulnerability Breakdown**: Counts and severity ratings (Critical, High, Medium, Low) of identified vulnerabilities across dependencies and source code.
- **Mean Time to Remediate (MTTR)**: Average time elapsed between vulnerability discovery/disclosure and successful patch deployment.
- **Dependency Freshness**: Percentage of third-party packages operating on latest stable releases vs. those requiring updates.
- **Audit & Scan Coverage**: Summary of automated static analysis (SAST), software composition analysis (SCA), and dynamic testing executions.

---

## 2. Reporting Cadence
- **Frequency**: Published **bi-annually** (every 6 months, aligning with mid-year and end-of-year reviews), with urgent interim security advisories published ad-hoc when necessary.

---

## 3. Target Audience
- **Primary Audience**: Core maintainers, security auditors, project stakeholders, and the wider open-source community seeking visibility into TeachLink's security health.
